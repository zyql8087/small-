# Snap-through 探针 — 仿真实验计划指导（交给 codex 执行）

> 目标：用**位移/弧长控制 + 大变形**重跑折纸力-位移曲线,判断能否得到**定性多样**的曲线
> (平台 / 负刚度 / snap-back / 多峰),而不是现有 NR 力控小变形的单调轻微硬化。
> 这是整个折纸方向的**决策门**:通过 → 扩量做正式数据集 + 实验;不通过 → 换 kirigami / 屈曲超材料。
>
> 本目录已备好 3 个工具(Claude 设计,codex 负责跑通/调参/扩量):
> - `matlab/GenerateSnapProbeCurves.m` — DC/MGDCM 大变形曲线生成器(探针)
> - `detect_curve_diversity.py` — 曲线形态分类 + 多样性判据(出 PASS/FAIL)
> - `select_abaqus_validation_samples.py` — 选 SWOMPS↔Abaqus 对照样本 + 出对照计划

---

## 0. 关键背景(给 codex 的上下文)

- 现有生产脚本 `miura_nonlinear_v2/matlab/GenerateOrigamiForceDisplacementCurves.m` 用
  `ControllerNRLoading`(**力控** NR),只到 0.015 m 小变形 → 曲线单调、只差量级。
- SWOMPS 自带两个能走 snap 的控制器(均在 `external/OrigamiSimulator/00_SourceCode/`):
  - `ControllerDCLoading` = 广义位移控制(弧长),`loadHis` 存的是**载荷因子 λ**,实际力 = λ × 参考载荷;
    需要 `selectedRefDisp=[node,dir]`。能抓 **snap-through**。
  - `ControllerMGDCMLoading` = 改进广义位移控制,最稳,能抓 **snap-back**(位移回退)。
  - 调用方式:`ori.loadingController{1}={"DC",ctrl}` 或 `{"MGDCM",ctrl}`,然后 `ori.Solver_Solve()`。
  - 参考可运行例子:`01_Example_Mechanical_Loading/Example01_Bistable4Vertex.m`(双稳态 DC+MGDCM)、
    `Example03_MiuraBeamFold.m`(Miura 折叠 MGDCM)。
- 探针脚本已经按上述接口把 NR 换成 DC/MGDCM,几何/材料与生产脚本**完全一致**(L=0.2、γ=70°、
  panelE/creaseE 来自参数、ν=0.3、ρ=1200)。

## 2. 步骤 A — 跑 50 样本探针(MATLAB)

先用 50 个 Miura 样本试跑(每样本 6 工况)。在 MATLAB 里:

```matlab
addpath(genpath("F:\small++\external\OrigamiSimulator\00_SourceCode"));

GenerateSnapProbeCurves( ...
   "F:\small++\origami_experiments\curve_dataset\miura_nonlinear_v2\jobs_miura\parameters.csv", ...
   "F:\small++\origami_experiments\curve_dataset\probes\snap_probe\raw_curves", ...
   "SimulatorRoot", "F:\small++\external\OrigamiSimulator", ...
   "LoadingMode", "displacement_dc", ...   % 先 DC;若需 snap-back 再试 "arclength_mgdcm"
   "CurvePoints", 80, "LambdaBar", 0.5, "IterMax", 50, ...
   "StartIndex", 1, "EndIndex", 50, "Overwrite", true);
```

**调参要点(codex 的核心活)** —— `LambdaBar` 决定 80 步走多远:
- 曲线没进入大变形/没出现非线性(还是直线)→ **调大 `LambdaBar`**(0.5 → 1 → 2 …);
- 求解发散 / `failures.log` 报错多 → **调小 `LambdaBar`** 并增大 `IterMax`(50 → 80);
- 目标:多数样本 80 步能走到明显大变形(折叠角显著变化 / 出现刚度下降)。
- 若 DC 仍抓不到 snap-back,换 `LoadingMode="arclength_mgdcm"`(MGDCM 无需 selectedRefDisp)。
- `axial`(+x,手风琴折叠)比 `bending` 更可能出 snap,先重点看 axial 工况。

> 产物:`snap_probe/raw_curves/<sample_id>.csv`(列 schema 与生产一致,另加 loading_mode/lambda_bar)。

## 3. 步骤 B — 多样性判据(Python,出 PASS/FAIL)

```powershell
& $PY "$PROBE\detect_curve_diversity.py" --curves-dir "$PROBE\raw_curves" --pass-threshold 0.25
```

输出 `curve_diversity_summary.json` + `_per_curve.csv`,并打印各形态占比:
`monotone_hardening / monotone_softening / plateau / snap_through / snap_back / multi_peak`。

**决策门(PASS 条件):**
- **"有意思曲线"占比 ≥ 25%**(snap_through + snap_back + multi_peak + plateau + softening),
- 且其中 **snap/plateau 类 > 0**(不能全是 softening)。
- 若 PASS → 进入步骤 C + 扩量;若 FAIL → 见步骤 E(调参再试一轮,仍不行就换结构族)。

## 4. 步骤 C — SWOMPS↔Abaqus 对照清单 + 高保真验证

## 5. 步骤 D — 通过后:retrofit 生产脚本 + 扩量(codex)

探针 PASS 且 Abaqus 定性吻合后,把位移控制并入生产脚本,然后全量重跑:

**retrofit `miura_nonlinear_v2/matlab/GenerateOrigamiForceDisplacementCurves.m`:**
1. 加 `addParameter(p,'LoadingMode',"displacement_dc")`、`'LambdaBar'`、`'RefUnitForce'`、`'IterMax'`。
2. 把探针里的 `runLoadCaseDispControl`(DC/MGDCM 分支 + 力=λ×参考载荷 提取)移植进去,
   作为 `runLoadCase` 的替代;`LoadingMode=="force_nr"` 时仍走原 NR 逻辑(保留向后兼容)。
3. 其余(几何 `buildOrigami`、条件表、CSV 写出、physics 列)**不动**,保证打包脚本零改动。
4. 全量重跑 2000 样本 → `build_curve_dataset_npz.py` 打包(schema 不变,直接复用)。

> 打包脚本 `build_curve_dataset_npz.py` 无需改:它按 step 1..80 读 force/displacement/physics,
> DC 模式下 displacement 可能非单调(snap-back),但打包按 step 存,不受影响;多样性已在步骤 B 验证。

## 6. 步骤 E — 决策树

| 探针结果 | 行动 |
|---|---|
| PASS + Abaqus 定性吻合 | retrofit + 全量重跑 → 训练你的算法 → 建立"曲线特征↔功能"映射 → 设计 demo → 打印实测 |
| PASS 但 Abaqus 显示 snap 是 bar-and-hinge 假象 | 关键设计点改用 Abaqus 数据,或缩小设计空间;考虑换屈曲超材料 |
| FAIL(曲线仍不够多样) | 先调 `LambdaBar`/换 MGDCM/换载荷方向再试一轮;仍 FAIL → 换 **kirigami(大拉伸)** 或 **屈曲超材料(曲线最丰富)**,本套工具(检测/选样/计划)可直接复用 |
