# Small++ GitHub 同步与 README 重构设计

> 日期：2026-08-27
>
> 状态：用户已批准
>
> 目标仓库：`https://github.com/zyql8087/small-`
>
> 目标分支：`small++`

## 1. 目标

将本地 Small++ 工作区现有的 TPMS 研究成果整合到一个新的 `small++` 分支，并发布到 GitHub 的 `zyql8087/small-` 仓库。发布内容应保留 M03、M04、GC-GraphFormer 和方法约束 Diffusion 的可追溯提交历史，同时纳入各工作树中尚未提交但属于当前 TPMS 方向的代码、研究计划、报告和配置。

根目录 `README.md` 将重写为中文主文，并提供英文项目标题与一句话摘要。README 必须准确反映当前研究主线和已有实现，不把规划中的 Abaqus 或物理实验写成已完成成果。

## 2. 分支整合策略

采用线性、精选式整合：

1. 以 `codex/paper-a-gc-graphformer` 为新分支基线。该分支已经连续继承 M03 连续 CSG、M04 双描述符接口、GC-GraphFormer 和方法约束 Diffusion 边界。
2. 将提交 `db0d239` 中“保留 TPMS、移除折纸材料”的清理变更叠加到新分支。
3. 汇总当前工作区和其他工作树中的未提交 TPMS 内容；同一路径存在多个版本时，先比较差异，再选择信息更新且与当前研究主线一致的版本。
4. 将设计说明、实施计划和重写后的 README 作为独立提交保留，便于审阅和追踪。

不采用 squash 快照，因为它会丢失研究里程碑历史；也不以 merge commit 作为默认方案，以免在发布分支中引入不必要的分叉结构。

## 3. 内容边界

### 3.1 纳入内容

- `paper_A_reliable_inverse_design/` 下的 TPMS 几何编译器、模型代码、测试和工具；
- Paper A 当前研究计划、正式研究设计、导师汇报、项目记录、学习指南和实施计划；
- M03、M04、GC-GraphFormer 和 Diffusion 边界相关的源码、配置、测试与紧凑验证结果；
- 人工维护的 `.qoder` 状态说明和研究配置；
- 根目录共享研究工作流、配置、Git 属性和忽略规则。

### 3.2 排除内容

- 所有 `**/.qoder/repowiki/**` 自动生成知识库，包括旧折纸知识库和可能过时的 TPMS 模型知识库；
- 已在 `db0d239` 中移除的折纸实验、数据、图表、报告和模型产物；
- 大型或可再生成的数据集、模型权重、原始仿真输出、日志、缓存和临时工作树；
- 与当前 TPMS 方向无关的本地环境状态。

排除仅影响新分支内容，不删除其他工作树中的原始文件。

## 4. README 信息架构

README 采用以下结构：

1. **标题与摘要**：英文标题和一句话英文摘要，随后给出中文定位；
2. **研究问题**：说明机制分辨经验可实现域、等响应机制分歧、扰动敏感性和证据门控；
3. **技术路线**：确定性几何编译器 → Abaqus 场数据 → Graph Transformer 前向验证 → Diffusion 多候选生成 → 证据门控 → 物理实验；
4. **当前成果**：明确区分已经实现的 M03、M04、GC-GraphFormer/Diffusion 边界与尚待完成的实验阶段；
5. **仓库结构**：给出源码、配置、测试、计划和报告的入口；
6. **快速开始**：提供可由当前仓库直接执行的 MATLAB 和 Python 验证命令；
7. **数据与证据约定**：说明大型产物不入库，以及有限域、有限预算下结论的表述边界；
8. **路线图**：列出 Gate 0、场数据生成、模型验证、Abaqus 裁决和打印压缩实验的后续顺序。

README 不使用“证明物理不可实现”“覆盖全部 TPMS”或“实验已经验证”等超出当前证据的表述。

## 5. 验证与发布

发布前执行以下验证：

- 检查工作区，确认没有意外纳入 `repowiki`、折纸目录、大型权重或原始仿真文件；
- 对新分支运行 `git diff --check`，排除空白和补丁格式错误；
- 运行仓库现有 MATLAB 测试入口；
- 运行最新 TPMS Python 测试套件，并记录通过、跳过或因环境缺失而无法运行的项目；
- 检查 README 中的相对链接和命令是否对应真实路径；
- 检查新分支提交历史确实包含 M03、M04 和 GC-GraphFormer 里程碑；
- 配置目标远端并推送 `small++`；推送后读取远端引用，核对远端分支提交与本地 HEAD 一致。

## 6. 错误处理

- 若清理提交与最新 TPMS 分支发生冲突，以“保留 TPMS、移除折纸”为原则逐文件解决，并单独审阅 README 与 `.gitignore`；
- 若多个工作树中的未提交文件冲突，不覆盖原文件，先比较内容并在新分支中形成经审阅的最终版本；
- 若 GitHub 认证失效，保留已完成的本地 `small++` 分支和提交，在重新认证后继续推送；
- 若测试失败，不把分支描述为验证通过；记录失败证据并区分代码失败与本机依赖缺失。

## 7. 完成标准

任务完成需要同时满足：

- 本地存在名为 `small++` 的整合分支；
- 分支包含已确认的全部 TPMS 提交和精选未提交内容；
- 自动生成 repowiki 与折纸材料未进入分支；
- README 与当前“机制分辨经验可实现域”方向一致；
- 可运行的项目验证已经执行并有新鲜结果；
- GitHub `zyql8087/small-` 上的 `small++` 分支指向与本地相同的提交。
