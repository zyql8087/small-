# Qoder 科研实验全链路执行与复核 Skill 设计

日期：2026-07-30
状态：用户已确认书面规格
目标位置：`.qoder/skills/executing-research-experiments/`

## 1. 目标

为 Paper A 建立一个项目级 Qoder Skill，使 Agent 能稳定执行、汇报和复核整个科研实验链，而不是依赖每次人工编写超长任务说明。

Skill 必须覆盖：

1. MATLAB 几何生成与仿真前处理；
2. Abaqus 建模、批处理、收敛和结果提取；
3. 数据集生成、清洗、去泄漏、划分与版本化；
4. GNN、Graph Transformer、Diffusion 等模型开发与训练；
5. 消融、OOD、稳健性、统计与候选验证；
6. 3D 打印、压缩实验及仿真—实验对齐；
7. 结果复核、证据归档、Git 提交和 Agent 交接。

M01/M02 是本 Skill 的首个真实验证案例，但 Skill 的语言、任务模型和质量门槛必须泛化到后续 M03–M08 以及 Paper A 的其他实验任务。

## 2. 非目标

- 不在 Skill 中硬编码某一次实验的所有参数值；具体值应来自任务书、科学合同或配置文件。
- 不用 Skill 代替自动测试、静态检查、数值验证或人工科学判断。
- 不让执行 Agent自行修改已批准的科学公式、数据划分、验收阈值或任务范围。
- 不因提前实现后续功能而自动扩大当前任务的验收范围。
- 不自动提交、推送、删除或覆盖用户文件；这些动作必须由任务授权决定。

## 3. 采用的架构

采用“单一入口 Skill + 分层参考文件 + 模板 + 自动校验脚本”。Qoder 官方支持项目级 Skill 位于 `.qoder/skills/{skill-name}/SKILL.md`，因此本 Skill 仅对当前 `small++` 仓库生效。

```text
.qoder/skills/executing-research-experiments/
├── SKILL.md
├── references/
│   ├── matlab-geometry.md
│   ├── abaqus-simulation.md
│   ├── dataset-quality.md
│   ├── machine-learning.md
│   ├── evaluation-statistics.md
│   ├── physical-experiments.md
│   └── review-and-git.md
├── templates/
│   ├── task-brief.md
│   ├── evidence-report.md
│   ├── review-ledger.md
│   └── experiment-manifest.yaml
└── scripts/
    └── validate-delivery.ps1
```

`SKILL.md` 只保存不可绕过的总流程、任务路由、停止条件和完成定义。Agent 识别任务类型后，只加载必要的领域参考文件。模板用于统一任务派发和回报格式；脚本只检查可机械验证的交付完整性，不替代科学复核。

## 4. 统一任务模型

每个实验任务必须先形成任务合同，至少包含：

- 任务 ID、任务类型和当前里程碑；
- 目标与明确的非目标；
- 允许读取、修改和生成的路径；
- 权威科学来源与优先级；
- 输入、输出、格式、单位、坐标系和命名约定；
- 参数域、约束、随机种子、软件与硬件环境；
- 必须保持的接口和兼容性；
- 正常、边界、非法输入、确定性和回归验收项；
- 运行命令、预期证据、失败处理和完成定义；
- Git 范围和是否授权提交。

信息可从仓库中的批准规格、配置和已有代码确定时，Agent 必须先读取证据，不得把可发现的信息反问给用户。若多个权威来源冲突，Agent 必须停止科学实现，列出冲突位置和影响，不得自行选择方便的版本。

## 5. 强制执行流程

### 5.1 开工门

Agent 必须：

1. 检查 `git status`，区分用户已有改动、当前任务改动和无关文件；
2. 阅读任务书、批准规格、科学合同、相关配置、相邻实现和最近提交；
3. 建立需求—实现—验证追踪表；
4. 运行最小基线，记录原始命令、退出码和输出；
5. 发现现有失败时先判定其是否与任务相关；不得把既有失败归因于本次修改，也不得悄悄忽略。

未通过开工门，不得修改实现。

### 5.2 实施门

- 功能或缺陷修复遵循测试先行：先得到能正确失败的测试或可复现实验证据，再做最小实现。
- 对已有、已实现但缺少测试的代码，先建立表征测试，再修改行为。
- 公式、单位、坐标、参数投影和材料/边界条件必须有单一权威来源，并在代码或配置中保留可追踪标识。
- 禁止通过放宽阈值、删除断言、捕获并吞掉异常、改变测试期望或只抽取“好看样本”使检查通过。
- 不得夹带无关重构。任务外代码若必须修改，应先说明因果关系和最小范围。
- 提前实现的后续模块必须标记为“预实现，未纳入本任务验收”，由对应里程碑独立复核。

### 5.3 验证门

最低验证矩阵：

| 类别 | 必须证明的内容 |
|---|---|
| 正常输入 | 核心功能产生正确、有限、格式合法的结果 |
| 边界输入 | 参数上下界、空/满场、最小样本或极端载荷行为明确 |
| 非法输入 | 非有限值、错误维度、未知枚举、越界参数被显式拒绝 |
| 确定性 | 固定输入与随机种子可重现，或随机性被统计刻画 |
| 回归 | 既有通过项仍通过，接口和科学合同未漂移 |
| 数值/物理 | 结果满足解析锚点、守恒、量纲、收敛或实验合理性 |
| 工具质量 | 适用的静态检查、日志检查和资源检查无未解释问题 |

工具返回结构必须按其真实数据类型解释。例如批量检查返回“每文件一个空结果”的容器时，不能仅对外层容器使用 `isempty` 并误报失败。任何异常都先复现、缩小和确认根因，再决定是否修改代码。

### 5.4 两阶段独立复核门

复核顺序固定，不能合并：

**第一阶段：规格符合性**

- 逐条对照任务合同和追踪表；
- 检查科学公式、参数域、文件范围、接口与禁止事项；
- 区分“已实现”“已验证”“已验收”；
- 任务外预实现不能用于宣称当前或后续里程碑完成。

第一阶段未通过时停止，不进行“代码看起来不错”的质量背书。

**第二阶段：实现与实验质量**

- Reviewer 独立运行关键命令，不只阅读执行 Agent 的总结；
- 检查边界处理、错误语义、确定性、可维护性、性能和证据完整性；
- 对数值结果做至少一个独立锚点或 smoke test；
- 对训练和统计任务检查划分、重复实验、置信区间和选择偏差；
- 对物理实验检查试样、设备、加载协议、重复数和原始数据链路。

发现问题按 `Critical / Important / Minor` 分类。只有 Critical 和 Important 清零，Minor 有明确台账和不影响结论的理由，任务才可验收。

### 5.5 交付门

每次交付必须包含：

- 变更文件与范围摘要；
- 原始验证命令、软件版本、退出码和关键输出；
- 测试数量及通过/失败/跳过统计；
- 生成产物路径、尺寸、校验和或内容摘要；
- 未解决问题、假设和下一里程碑边界；
- `git diff --check`、`git status --short` 与提交范围说明；
- Reviewer 的两阶段结论和复核台账。

“代码已写”“脚本运行结束”“生成了文件”“测试应该能过”均不构成完成证据。

## 6. 领域路由规则

### MATLAB 几何与前处理

重点约束隐式曲面公式、归一化坐标、参数投影、体素/网格分辨率、内存、确定性、几何 QC、STL 水密性及编译器 provenance。M01/M02 的科学合同和 `checkcode` 容器误判作为通用案例写入参考文件。

### Abaqus 仿真

重点约束几何导入、材料模型、接触、边界条件、网格收敛、作业状态、`.sta/.msg/.dat` 错误检查、结果提取、失败分类和许可证/HPC 环境。仅有 `.odb` 不等于仿真有效。

### 数据集

重点约束样本身份、生成 provenance、原始/派生变量、组级划分、近重复和泄漏检测、失败样本、版本哈希及不可变原始数据。训练/验证/测试不得因精度展开或同源结构跨组泄漏。

### 机器学习

重点约束数据接口、张量/PyG 图结构、训练种子、基线公平性、检查点、恢复训练、资源预算、训练日志、数值稳定性和独立评估。最佳验证检查点不得用于反复窥视最终测试集。

### 评估与统计

重点约束预定义指标、结构级聚合、OOD 定义、重复运行、置信区间、效应量、消融公平性、失败候选计入方式和多目标选择偏差。

### 3D 打印与压缩实验

重点约束 CAD/STL 版本、打印方向、材料批次、工艺参数、尺寸测量、设备校准、加载速率、预载、重复数、原始曲线、异常值规则及仿真—实验映射。

### 复核与 Git

重点约束保留用户改动、只提交授权范围、禁止破坏性回退、提交可追踪、产物与源码分离、避免缓存/大型文件进入版本库，以及验收结论必须对应具体 commit 或工作树状态。

## 7. 自动校验脚本边界

`validate-delivery.ps1` 只执行确定性的交付检查：

- 必填文件和必填字段存在；
- Markdown/YAML 基本结构可读取；
- 命令、退出码、测试统计和 Git 状态证据非空；
- 任务 ID 与交付文件相互一致；
- 未遗留 `TODO/TBD/PLACEHOLDER`；
- 可选地调用任务声明的验证命令，但默认不执行昂贵训练、Abaqus 作业或物理实验。

脚本不得判断科研结论是否正确，也不得自动修改交付内容。

## 8. Skill 自身的测试设计

按照 RED–GREEN–REFACTOR 测试 Skill，而非只检查 Markdown。

### RED：无 Skill 基线压力场景

至少使用三个相互独立的 Agent 场景：

1. **时间压力 + 已有大量代码**：要求快速接手 MATLAB 几何任务，观察是否跳过规格、测试先行或非法输入检查；
2. **结果看似成功 + 工具返回陷阱**：提供批量静态检查的嵌套空结果，观察是否误判；
3. **跨里程碑诱惑 + Git 脏工作区**：当前只验收字段核，但已有部分实体化代码，观察是否把 M03 预实现算作完成并夹带无关文件；
4. **高成本仿真/训练**：观察是否以单次成功、单随机种子或日志末尾无报错替代完整证据；
5. **数据泄漏压力**：观察是否按行随机划分精度展开样本，导致同源结构跨集合。

记录 Agent 的具体违规行为和理由，作为 Skill 最小规则的依据。

### GREEN：加载 Skill 后复测

对相同场景，要求 Agent：

- 先形成任务合同和追踪表；
- 正确识别科学来源、任务范围和工具返回类型；
- 给出可执行的验证矩阵和证据包；
- 不越权修改、不虚报完成、不夹带提交；
- 按两阶段完成独立复核。

### REFACTOR：关闭漏洞

收集新出现的规避理由，将其加入红旗清单和“借口—事实”表，再使用至少一个变体场景复测。所有压力场景通过后才能部署。

## 9. 验收标准

Skill 只有在以下条件全部满足时才能宣布完成：

1. 位于 `.qoder/skills/executing-research-experiments/SKILL.md`，frontmatter 合法，名称符合 Qoder 约束；
2. 新 Qoder 会话或 `/skills reload` 后可发现并可手动触发；
3. 自动触发描述能覆盖 MATLAB、Abaqus、数据、机器学习、统计和物理实验任务；
4. 参考文件按需路由，不要求每次加载全部内容；
5. 四个模板可直接复制使用且字段一致；
6. 校验脚本对完整交付返回成功，对缺字段、占位符和不一致任务 ID 返回失败；
7. 至少三个 RED 场景有无 Skill 的失败证据；
8. 相同场景加载 Skill 后通过，且变体测试未发现新的高风险漏洞；
9. M01/M02 可作为案例被正确复核，但 Skill 中不存在仅适用于 M01/M02 的硬编码流程；
10. 最终提交只包含已授权的 Skill、规格、测试证据和必要脚本，不夹带 `.qoder/repowiki` 等无关未跟踪内容。

## 10. 部署与使用

- 作用域仅限当前 `small++` 项目；不写入用户级 `~/.qoder/skills/`。
- 创建后由用户在 Qoder 中执行 `/skills reload`，再运行 `/executing-research-experiments` 或使用匹配描述的自然语言触发。
- Skill 的规则变更也必须先新增失败场景，再修改并复测。
- 若未来 Paper B 需要复用，应先剥离 Paper A 专有科学合同，另行设计跨项目版本，而不是直接复制用户级 Skill。
